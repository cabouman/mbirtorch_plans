Blueprints: Time-resolved 4D reconstruction

A 4D reconstruction for mbirtorch that models each view at its own acquisition time and uses a motion-compensated temporal prior. It is for continuous-rotation scans of objects that move faster than the current MACE4D frames can follow. One blueprint per component. Start at the top and read down.

Core components

1. Theory

settled

It defines the time-resolved data term, the motion model, and the motion-compensated temporal prior. It also gives the MACE iteration that combines them with the spatial denoisers.

2. Software Architecture

settled

It shows how the new pieces extend MACE4DModel. The new pieces are the data-fit agents that each hold two frames, the motion estimator, and the storage of the motion fields.

3. Hardware Mapping

for review

It gives what lives in host and GPU memory, what each processor computes, and what moves between them, with sizes and times. It sets a memory budget for each device, because one interval task holds about seven volumes. The motion needs three numbers per moving part per frame and one label volume, in place of a dense field that is three times the size of a frame.

4. User API

not started

It gives the script a user writes for a time-resolved run, and every new public name.

Optional components

5. Testing and Verification

not started

It compares the new method with the current MACE4D on a moving phantom with known motion. It also lists the tests of the new operators, such as an adjoint test and a one-frame run that must reproduce the standard 3D reconstruction.

Pre and Post Processing, Documentation, and Release and Maintenance were not chosen, because these parts work as they do for MACE4D now. Decisions and rejected alternatives are recorded, with dates, in decisions.md.
